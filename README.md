---

## 1. Характеристика объекта

Notepad++ — бесплатный редактор исходного кода и текстовый редактор для Windows. Он предназначен для создания и редактирования текстовых документов и программного кода. Официальный README указывает поддержку нескольких языков программирования и естественных языков, а также лицензию GPL.

Основные пользователи — разработчики, студенты, системные администраторы и другие пользователи Windows, которым нужен редактор текста и конфигурационных файлов.

**Источник:** [официальный репозиторий Notepad++](https://github.com/notepad-plus-plus/notepad-plus-plus).

Рассматривается версия 8.9.7. Границы исследования: загрузка файлов и сессий, обработка оконных сообщений Windows, пользовательские команды и установщик MSI. Исследование основано на документации репозитория и опубликованных технических описаниях уязвимостей; оно не является полным аудитом продукта.

## 2. Цель анализа

Оценить безопасность обработки файлов и межпроцессного взаимодействия в Notepad++ версии 8.9.7, определить риски, связанные с загрузкой пользовательских данных и установкой программы, и сформулировать рекомендации по их снижению.

## 5. Исследование объекта и применённые методы

### 5.1. Анализ документации

Изучен README официального репозитория. Он описывает Notepad++ как редактор исходного кода и замену стандартному Блокноту Windows. В репозитории доступны инструкции по сборке, правила участия в разработке, лицензия и сведения о поддерживаемых системах.

### 5.2. Анализ структуры

В корне репозитория присутствуют каталоги PowerEditor, scintilla, lexilla, boostregex, а также BUILD.md, CONTRIBUTING.md, README.md и SUPPORTED_SYSTEM.md. Это подтверждает модульную организацию проекта на уровне репозитория. Полное исследование зависимостей и связей между модулями не выполнялось.

### 5.3. Статический анализ опубликованных сведений

Изучены официальные Security Advisories. В них приведены имена файлов, фрагменты кода, условия возникновения дефектов и затронутые версии. Эти сведения использованы как документальные свидетельства. Самостоятельный запуск анализатора C/C++ не выполнялся.

### 5.4. Анализ исправлений

Сопоставлены затронутые и исправленные версии. Для проблемы UNC-путей в сессиях и переполнения буфера UTF-16 в advisories указана версия 8.9.8 как исправленная.

### 5.5. Динамическое тестирование

На установленной копии программы тестирование не проводилось. Тестовые файлы и инструменты проверки памяти не запускались. Результаты основаны на опубликованных технических описаниях, а не на самостоятельном эксперименте.

## 6. Выявленные проблемы и риски

### 6.1. Недостаточная проверка UNC-пути в файле сессии

В advisory [GHSA-fw3m-3qpq-pvr8](https://github.com/notepad-plus-plus/notepad-plus-plus/security/advisories/GHSA-fw3m-3qpq-pvr8) описано, что проверка UNC-путей применялась к некоторым элементам сессии, но не к FileBrowser/root foldername. При загрузке специально подготовленного файла сессии Windows могла инициировать NTLM-аутентификацию без предупреждения.

Возможное последствие — раскрытие NTLMv2-хеша и риск дальнейших атак на сетевую учётную запись. Затронуты версии до 8.9.7; исправлена в 8.9.8.

**Рекомендация:** проверять все UNC-пути до обращения к ним и показывать предупреждение.

### 6.2. Недостаточная проверка отправителя WM_COPYDATA

В advisory [GHSA-pg39-63h5-cx35](https://github.com/notepad-plus-plus/notepad-plus-plus/security/advisories/GHSA-pg39-63h5-cx35) описано, что Notepad++ разрешал получение WM_COPYDATA для интеграции с оболочкой Windows, но обработчик не проверял отправителя. Локальный процесс с низким уровнем целостности мог передать путь к файлу, после чего Notepad++ открывал его.

Риск — принудительное открытие файла в контексте редактора, в том числе при повышенных правах процесса. Для затронутых версий до 8.9.7 исправленная версия в advisory не указана.

**Рекомендация:** проверять отправителя и контекст сообщения.

### 6.3. Риск повышения привилегий через WM_COMMAND

В advisory [GHSA-grw6-cw7j-3qfg](https://github.com/notepad-plus-plus/notepad-plus-plus/security/advisories/GHSA-grw6-cw7j-3qfg) для версии 8.9.7 описана комбинация слабых мест: WM_COMMAND проходит через границу уровней целостности Windows, а ключ проверки shortcuts.xml основан на MachineGuid, доступном для чтения обычным пользователям.

По описанию advisory локальный пользователь мог сформировать изменённую конфигурацию и инициировать выполнение команды в повышенном экземпляре Notepad++. Возможное последствие — выполнение команды с более высокими правами.

**Рекомендация:** не использовать общедоступное значение как секретный ключ, защищать ключи и проверять источник команд.

### 6.4. Переполнение буфера при обработке UTF-16

В advisory [GHSA-8jjh-4rq6-r2h8](https://github.com/notepad-plus-plus/notepad-plus-plus/security/advisories/GHSA-8jjh-4rq6-r2h8) описано переполнение кучи при преобразовании UTF-16 в UTF-8 в версии 8.9.7. Пара суррогатных символов могла разделяться между блоками чтения, а размер выходного буфера рассчитывался только по текущему блоку. Это могло привести к записи за пределами выделенной памяти.

Подтверждены повреждение памяти и аварийное завершение; выполнение произвольного кода не доказано. Проблема исправлена в 8.9.8.

**Рекомендация:** учитывать состояние преобразователя между блоками и добавить граничные тесты.

### 6.5. Инъекция PowerShell через параметр установщика MSI

В advisory [GHSA-97rx-3h53-4cfj](https://github.com/notepad-plus-plus/notepad-plus-plus/security/advisories/GHSA-97rx-3h53-4cfj) описана проблема MSI версии 8.9.7: путь установки подставлялся в PowerShell-строку без безопасного экранирования. Апостроф в имени каталога мог изменить структуру команды.

При установке со специально сформированным параметром INSTALLFOLDER возможно выполнение внедрённой команды при следующем входе пользователя. Для эксплуатации требуется влияние на параметр и запуск установщика администратором; автоматическое получение SYSTEM не утверждается.

**Рекомендация:** отделить данные пути от текста команды и безопасно передавать путь.

Для двух проблем в advisories указана версия 8.9.8 как исправленная; для остальных исправленная версия на страницах advisories не указана.

## 8. Итоговое заключение

В результате анализа установлено, что Notepad++ имеет открытый исходный код, публичный репозиторий и документацию, позволяющие изучать структуру и историю изменений. Вместе с тем официальные технические описания уязвимостей показывают существенные риски в отдельных механизмах обработки файлов, сессий, межпроцессных сообщений и параметров установщика.

Наиболее значимыми по возможным последствиям являются риск повышения привилегий через WM_COMMAND, утечка NTLM-хеша при загрузке файла сессии и инъекция PowerShell через параметр MSI. Также выявлено переполнение буфера при обработке специально сформированного UTF-16-файла и недостаточная проверка отправителя WM_COPYDATA.

Для снижения рисков рекомендуется использовать актуальную версию программы, проверять происхождение установочных файлов, не запускать редактор с повышенными правами без необходимости, осторожно открывать файлы сессий из неизвестных источников и устранять причины уязвимостей на уровне проверки входных данных и межпроцессного взаимодействия.

**Ограничения исследования:** анализ проводился по официальному репозиторию и опубликованным описаниям уязвимостей. Самостоятельная сборка проекта, запуск статического анализатора, динамическое тестирование и проверка исправлений на установленной программе не выполнялись. Работа не является независимым аудитом всей кодовой базы; выводы ограничены выбранной версией и рассмотренными компонентами.
